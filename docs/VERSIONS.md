# Версии главной страницы — как это устроено и как добавить новую

Система, чтобы показывать заказчику несколько вариантов главной страницы
одновременно и дать ему выбрать.

- **Страница выбора (хаб):** `/versions` — список версий с описанием и кнопкой.
- **Сама версия:** `/versions/<id>` — полноценная главная + плашка сверху с
  названием версии и ссылкой назад к списку.
- **Боевая главная `/`** — это всегда **версия 1**, тот же самый код (см. ниже).

⚠️ `/versions` и `/versions/*` **открыты публично**, без префикса `/admin` — чтобы
ссылку можно было просто отправить клиенту. Остальной сайт по-прежнему закрыт
(`middleware.ts`). У всех этих страниц стоит `robots: noindex` — в поиск не попадут.

---

## Как добавить новую версию — 2 файла + 1 компонент

### Шаг 1. Описать версию в реестре

[`lib/versions.ts`](../lib/versions.ts) — добавить запись в массив `VERSIONS`:

```ts
{
  id: "v3",                       // станет адресом /versions/v3
  title: "Версия 3 — Новый HERO",  // текст кнопки и плашки
  description: "Первый экран во всю высоту, фото двигаются при прокрутке.",
  status: "draft",                 // ready | draft | archived
},
```

Про `status`:
- `ready` — показываем заказчику, идёт первой в списке;
- `draft` — в работе: на хабе видна, но помечена «черновик» и уходит вниз списка;
- `archived` — с хаба пропадает, но прямая ссылка продолжает работать
  (удобно, когда вариант отклонили, но терять не хочется).

### Шаг 2. Сделать компонент версии

Создать `components/versions/home-v3.tsx` по образцу
[`home-v1.tsx`](../components/versions/home-v1.tsx) (базовая) или
[`home-v2.tsx`](../components/versions/home-v2.tsx) (с анимациями):

```tsx
import type { HomeData } from "@/lib/home-data";

export function HomeV3({ data }: { data: HomeData }) {
  const { homePage, tours, reviews, customTour, faqItems, primaryContacts } = data;
  return <main className="min-h-screen">{/* своя раскладка секций */}</main>;
}
```

Данные загружать **не нужно** — они уже приходят готовыми в `data`
(см. [`lib/home-data.ts`](../lib/home-data.ts), один запрос на все версии).

### Шаг 3. Связать id с компонентом

[`components/versions/registry.tsx`](../components/versions/registry.tsx) — одна строка:

```tsx
export const VERSION_COMPONENTS = {
  v1: HomeV1,
  v2: HomeV2,
  v3: HomeV3,   // ← добавить
};
```

Всё. Роут `/versions/v3` и карточка на хабе появятся сами.

## Главное правило: не копировать код между версиями

Версии должны **переиспользовать** секции из `components/sections/`, а не быть
копиями страницы с правками. Иначе через три версии любая правка контента
превращается в «поправить в пяти местах», и версии начинают расходиться по сути,
а не по оформлению.

Как отличать версии, не копируя:

| Что меняется | Как делать |
|---|---|
| Порядок/состав блоков | просто другая последовательность секций в компоненте версии |
| Анимация появления | обернуть секции в `<Reveal>` — см. `home-v2.tsx` |
| Стили поверх готовых секций | класс-обёртка + правило в `globals.css`, ограниченное этим классом (`.animated-preview` в `home-v2`, `.v5-scene` в `home-v5` — образцы) |
| Один блок реально другой | сделать **новый компонент секции** рядом со старым (например `hero-section-fullscreen-v4.tsx` рядом с `hero-section.tsx` и `hero-section-fullscreen.tsx`) и подключить только в нужной версии. Старые не трогать |

Чего не делать: копировать `home-v1.tsx` целиком ради двух изменённых строк;
добавлять в существующие секции пропы вида `variant="v3"` (секции начнут знать
про версии — их станет невозможно читать).

## Что общего у всех версий

Приходит от `app/layout.tsx`, отдельно в версии не добавляется:
- шапка (`Header`), подвал (`Footer`), плавающая кнопка контактов;
- шрифты и глобальные стили.

Данные — общий `getHomeData()`. Если в Sanity появилось новое поле, оно
добавляется **один раз** в `lib/home-data.ts`, и его сразу видят все версии.

⚠️ Правки в **общих** компонентах (`Footer`, `Header`, `FloatingContacts`) видны
**на всех версиях и на боевом сайте одновременно** — они не привязаны к
конкретной версии. Например, эффект «воды» в кольцах футера (`footer.tsx`,
SVG-фильтр `feTurbulence`) — общий, появляется везде. Перед такой правкой стоит
явно уточнить у заказчика, что она затронет продакшн, а не только черновик.

### Принудительное включение анимаций на `/versions/*`

`components/versions/force-motion.tsx` ставит `<html data-force-motion="true">`
на страницах версий — иначе системная настройка «уменьшить анимацию» (она была
включена у заказчика, из-за этого он не видел анимации при просмотре версий)
глушит все CSS-анимации, и оценивать становится нечего.

**Каждая новая CSS-анимация, которая должна быть видна на `/versions/*`,
обязана получить override-правило** вида:

```css
@media (prefers-reduced-motion: reduce) {
  .my-effect { animation: none; }
}

html[data-force-motion="true"] .my-effect {
  animation: myEffect 2s ease-in-out infinite !important;
}
```

Без этого override эффект будет молча пропадать именно там, где его должны
оценивать — это уже дважды случалось в этом проекте (волны в футере, потом
Ken Burns/маркер прокрутки в HERO) и оба раза не было заметно сразу.

## Грабли слоёв анимации: кто побеждает за одно и то же свойство

Все три бага ниже выглядели по-разному, но причина одна: **CSS-анимация сильнее
обычных объявлений (класса, `:hover`), а идущий переход сильнее анимации.** Это
спека, а не баг браузера. Когда за одно свойство борются слой появления секции и
собственный эффект элемента — получается рывок в момент, когда управление
переходит от одного к другому.

### 1. `animation-fill-mode` — только `backwards`, никогда `both`

`both` = `forwards` + `backwards`: доигравшая анимация **навсегда** оставляет за
собой свойство. Дальше любой `:hover` плавно доезжает за свои 300–800 мс, переход
заканчивается, управление возвращается к залипшей анимации — и элемент мгновенно
прыгает обратно. Именно так «дёргались» карточки туров.

`backwards` держит только стартовый кадр во время `animation-delay`, а после
завершения отпускает элемент. Визуально идентично, hover при этом работает.

### 2. Элемент со своим `:hover` — исключать из общей анимации появления

Если у элемента есть собственный эффект на `transform` (зум фото карточки),
общая анимация появления на том же свойстве конфликтует с ним всё время, пока
играет. Карточки в начале страницы попадают в кадр сразу, курсор часто приходит
именно в эти 0.6–1.1 с: hover будто не работает, а через секунду фото само
дёргается.

Опт-аут — атрибут `data-no-lift` на элементе + правило `animation: none`.
Он же исключает элемент из общего «подъёма ссылки на 2px» (`.v6-scene a:hover`):
подъём уводит нижнюю кромку карточки из-под курсора, наведение сбрасывается,
карточка падает обратно и снова ловит курсор — мигание.

### 3. Фото с постоянной прозрачностью — тоже исключать

Фоны VALUES/FOUNDERS/COLLAB приглушены статичным `opacity-45/55/60` прямо на
`<img>`. Общая анимация появления анимирует `opacity` к **1** и побеждает класс,
пока идёт: фото видно ярче задуманного, а в момент завершения прозрачность одним
кадром падает до 0.45 — на глаз «резко накрыло фильтром и сменился цвет».

Опт-аут — `data-static-photo` на обёртке фото. Секция и так получает общий wipe,
отдельное появление у таких фото не нужно.

**Практическое правило:** добавляя в версию анимацию на `img` или на карточки,
проверьте, нет ли у этих элементов собственного `:hover` или статичного класса на
том же свойстве. Если есть — исключайте атрибутом, а не «подгоняйте» значения.

## Проверить локально

```bash
npm run dev
```

- список версий — `http://localhost:3000/versions`
- конкретная версия — `http://localhost:3000/versions/v1`
- боевая главная (закрыта, только через обход) — `http://localhost:3000/admin/`

С телефона в той же Wi-Fi: заменить `localhost` на IP компьютера (`ipconfig`),
например `http://192.168.0.39:3000/versions`.

| `v6` | Кинематографичный скролл | draft | v4 + переработанный слой анимаций (`.v6-scene`/`.v6-cine`, источник — пакет `версия 6/` в корне репо от заказчика): каждая секция — wipe (подъём+масштаб+расфокусировка), заголовки — «шторка» (`clip-path`), карточки/списки — волна по очереди. Плюс более мягкий фильтр колец в футере (тоже общий для всех версий) |

**Известные несовпадения имён, если попадётся в старом коде:** `hero-section-fullscreen.tsx`
(без суффикса) принадлежит v3, `hero-section-fullscreen-v4.tsx` — v4/v5. Названия не
идеально симметричны (v3 появился раньше системы версий и получил файл без суффикса) —
при следующей уборке можно переименовать в `-v3.tsx` для единообразия, не критично.
