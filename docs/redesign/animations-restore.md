# Анимации на главной: как устроены, как настроить, как снять

> **Статус: анимации на главной ВКЛЮЧЕНЫ** (коммит `21b19b3` «Возвращены анимации
> версии 6 на боевую главную»). Проверка в одну строку — на живой странице должен
> находиться класс `v6-scene`:
>
> ```bash
> curl -sL http://localhost:3000/admin/ | grep -c v6-scene
> ```
>
> Ноль — значит слой отвалился, читайте раздел «Как включён».

## Зачем этот файл

Слой анимаций дважды пропадал с главной по одной и той же причине: он заперт под
класс `.v6-scene`, и стоит этому классу исчезнуть из разметки — все правила молча
перестают срабатывать, ошибки при этом нигде нет. Так вышло 25.08, когда боевой
главной стал облегчённый вариант «версия 8»: он делался как один из трёх вариантов
ДЛЯ СРАВНЕНИЯ МАСШТАБА, движение в нём выключали намеренно — заказчик сравнивал
только размеры. Вместе с v8 на `/` переехало и это отсутствие анимаций, хотя
кинематографичный слой версии 6 заказчик согласовал ещё 20.08.

Здесь: где что лежит, как включено, что проверять и как разбирать слой по частям,
если заказчик скажет «слишком много движения».

Смежное: [`lightweight-scale-plan.md`](lightweight-scale-plan.md) — про масштаб,
[`../VERSIONS.md`](../VERSIONS.md) — грабли слоёв анимации, [`backlog.md`](backlog.md).

## Как включён

В [`home-light.tsx`](../../components/home/home-light.tsx): `<main>` обёрнут в
`<div className="v6-scene">`, каждая секция — в `<Reveal className="v6-cine">`.

```tsx
<div className="v6-scene">
  <main className="min-h-screen">
    {homePage?.hero && <HeroSectionFullscreenV4 hero={homePage.hero} />}
    <Reveal className="v6-cine">{homePage?.about && <AboutSection about={homePage.about} />}</Reveal>
    {/* …и так каждая секция до FAQ */}
  </main>
</div>
```

Три вещи, которые нельзя переставлять:

1. **HERO без `<Reveal>`** — он сам себе первый экран и появляется по-своему
   (Ken Burns, маркер прокрутки). Так было во всех версиях с v2 по v6.
2. **`<script>` масштаба и `<PageScale>` — ВЫШЕ `.v6-scene`.** `FaqSection` меряет
   высоту аккордеона в своём `useLayoutEffect`; применись масштаб позже — она
   запомнит чужую высоту (подробности в комментарии `page-scale.tsx`).
3. **`prefers-reduced-motion` на главной соблюдается.** `<ForceMotion>` подключён
   только к `/versions/*`, где он был нужен: там заказчик оценивал саму анимацию,
   и приглушать её было бессмысленно. На `/` у пользователя с системной настройкой
   «уменьшить анимацию» секции появятся только прозрачностью, без сдвига и
   масштаба — это правильное поведение, менять не надо.

## Грабли (все уже наступали)

1. **`animation-fill-mode: backwards`, никогда `both`/`forwards`.** Доигравшая
   анимация с `forwards` навсегда забирает себе свойство и ломает `:hover` —
   элемент прыгает обратно в конце перехода. Так «дёргались» карточки туров.
2. **Элементы со своим `:hover` исключаются атрибутом `data-no-lift`.** Иначе общий
   подъём ссылок конфликтует с собственным эффектом элемента.
3. **Фото с постоянной прозрачностью исключаются атрибутом `data-static-photo`.**
   Это фоны VALUES, FOUNDERS, COLLAB: они приглушены постоянным `opacity`, а общая
   анимация появления фото гонит прозрачность к 1 и в конце резко роняет обратно.
4. **`Reveal` использует `threshold: 0`, а не долю площади.** С прежним `0.12`
   секции выше экрана могли не показаться никогда: видимая доля такого блока
   физически не достигает 12%, блок навсегда оставался `opacity: 0`, и казалось,
   что страница не листается дальше HERO. Не менять.
5. **Turbopack теряет правки CSS при горячей пересборке.** Правило есть в
   `globals.css`, а в отданном браузеру файле его нет; помогает рестарт
   `npm run dev`. Не верить, что правка применилась — проверять скачиванием
   скомпилированного CSS. За 25.08 ловили трижды.
6. **Не мерить, пока играет анимация.** У непроявленного элемента `opacity: 0` и
   `transform` — любой замер поймает не то. Это же касается `scripts/audit-scale.mjs`:
   он прокручивает страницу целиком и ждёт, но при правках слоя стоит перепроверить.

## Что проверять после правок слоя

Связка «анимации + уменьшенный масштаб v8» новая: анимации настраивались под
макетные кегли версии 6, а на главной они теперь в 0.68 от них.

1. **Заголовки.** «Шторка» открывает их через `clip-path`, высота шторки считается
   от строки — убедиться, что заголовки открываются целиком и не обрезаются.
2. **Три плашки** (ABOUT / FOUNDERS / COLLAB): выверенный ритм отступов
   42 / 22 / 38 / 34 / 34 при 1280. Анимация добавляет `transform` — проверить,
   что ритм не поехал.
3. **Волна карточек и списков** (`nth-child`, шаг 80 мс): VALUES (6 карточек),
   GUESTS (6 пунктов), REVIEWS, FAQ.
4. **Системная настройка «уменьшить анимацию».** DevTools → Rendering → Emulate CSS
   media feature `prefers-reduced-motion: reduce`. Убедиться, что страница не
   остаётся пустой: секции должны появляться хотя бы прозрачностью. Эта грабля уже
   стреляла — заказчик с такой настройкой не видел вообще никакого движения.
5. **Аудит масштаба** — `node scripts/audit-scale.mjs http://localhost:3000/admin/`,
   норма: оба списка пустые.
6. **Мобильная.** У блока есть отдельная ветка `@media (max-width: 1023.98px)` с
   более щадящими значениями — проверить и её.

## Как разобрать слой по частям

Если заказчик скажет «слишком много движения», всё правится в тех же строках
789–1021 `globals.css`, класс за классом:

- **убрать масштаб и расфокусировку, оставить подъём** — правило
  `.v6-scene .v6-cine[data-revealed="false"]`;
- **убрать «шторку» заголовков** — правила с `.v6-cine h2`;
- **убрать волну карточек** — правила с `[class*="grid"] > *` и `ul > li`;
- **убрать подъём кнопок при наведении** — правила `.v6-scene a:hover`.

Выключить слой целиком, ничего не удаляя, — снять класс `v6-scene` с обёртки в
`home-light.tsx`. Все правила перестанут срабатывать, CSS останется нетронутым.

**Открытый вопрос на будущее.** Логика «сайт должен ощущаться легче», ради которой
делали v8, и полуторасекундные wipe-переходы каждой секции немного спорят друг с
другом. Имеет смысл показать заказчику два варианта — полный слой и только мягкое
появление прозрачностью — и дать выбрать.
