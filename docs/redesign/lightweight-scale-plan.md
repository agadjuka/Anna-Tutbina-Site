# Облегчение главной: план вариантов «поменьше и повоздушнее»

**Запрос заказчика (2026-08-23, скрин переписки):**

> Мне кажется, сейчас на сайте не хватает ощущения лёгкости, он прям тяжёлый и ощущается
> громоздким. Может быть попробуем уменьшить масштаб типографики и расстояний/шрифтов?
> Например уменьшить заголовки/основной текст, сократить вертикальные отступы между
> заголовками/текстом. Наверное хочется в целом уменьшить визуальный масштаб сайта…
> Не хочется, чтобы каждый блок занимал целый экран. Хочется быстрее и легче проходить
> страницы. …вот тут наверное особенно бросается в глаза крупноразмерность (скрин блока GUESTS)

**Решение по форме работы (наше, с заказчиком не согласовано):** боевая главная `/`
**не трогается**. Варианты облегчения делаются как новые версии в уже существующей
системе `/versions` — тот же «разветвитель», через который выбирали версию 6.

попали в макет. Заказчик сейчас говорит, что сам макет крупен.

## 2. Что именно делает страницу «тяжёлой»

1. **Кегль основного текста 27 px.** Главный источник ощущения «громоздко».
2. **Шаг списка GUESTS 49 px при кегле 25.** Шесть коротких строк занимают 470 px.
3. **`min-height` секций.** ABOUT 922, VALUES 1020, GUESTS 1051, FOUNDERS 828,
   REVIEWS 711, FAQ 968, COLLAB 743. Даже когда контента меньше — блок всё равно
   разворачивается на экран.
4. **Крупные вертикальные отступы внутри блоков:** `space-y` 43 / 47 / 49 px,
   `mt` 60–68 px, `py` 55–98 px.
5. **Плотные визуальные плашки:** белые карточки VALUES с тенью, серые плашки строк
   FAQ, две сплошные оливковые полосы во всю ширину (ABOUT, FOUNDERS, COLLAB).

Чего в списке нет и не будет: шрифты, палитра, порядок блоков, контент.
Заказчик просил масштаб — меняем масштаб.

## 3. Механизм: один параметризованный слой CSS, ноль правок в боевых секциях

Все размеры на главной уже записаны по закону масштабирования
(`docs/design-system.md`): `min(X/1920*100vw, Xpx)`. Значит достаточно домножить
выражение на коэффициент — закон при этом сохраняется:

```css
font-size: calc(var(--ona-display) * min(4.17vw, 80px));   /* было min(4.17vw, 80px) */
```

Отсюда план:

- **Новый файл `app/globals.css` → секция «Облегчённые версии»** (по образцу
  `.v5-scene` / `.v6-scene`): правила, ограниченные атрибутом `html[data-ona-scale]`.
  Атрибут, а не класс-обёртка, — чтобы правило доставало и до футера
  (он живёт в `app/layout.tsx`, вне `{children}`, класс-обёртка его не накрывает).
- **Четыре переменные** на всю систему:

  | Переменная | Что масштабирует |
  |---|---|
  | `--ona-display` | H1/H2 блоков |
  | `--ona-text` | абзацы, пункты списков, названия карточек |
  | `--ona-micro` | надзаголовки, подписи, вопросы FAQ (уже мелкие — жмутся слабее) |
  | `--ona-space` | вертикальные отступы, зазоры сеток, `min-height` секций |

- **Правила пишутся вне `@layer`.** В Tailwind v4 все утилиты лежат в
  `@layer utilities`, а нелойерное правило бьёт любое лойерное независимо от
  специфичности — значит `!important` не нужен нигде.
- **Ширины текстовых колонок масштабируются вместе с кеглем.** Иначе разбивка строк
  поедет: у ABOUT H2 стоит `max-w: 800px` специально ради разбивки
  «ИСКУССТВО / ПУТЕШЕСТВОВАТЬ / КРАСИВО» — при уменьшенном кегле и прежней ширине
  заголовок сложится в две строки.
- **Полы читаемости остаются.** Пишутся как `max(11px, calc(...))`, чтобы уменьшение
  не утащило мелкий текст ниже читаемого (правило из `design-system.md`).
- **Секции, `home-v6.tsx`, боевая `/` — не трогаются вообще.** Ни одного изменённого
  файла в `components/sections/`.

Подключение варианта — как у `ForceMotion`: страница версии ставит
`document.documentElement.dataset.onaScale`. Плюс синхронный inline-скрипт в теле
страницы, чтобы атрибут появился до первой отрисовки и не было мигания
«сначала крупно, потом ужалось».

**Дополнительно только в v9** (осознанное отступление от макета Figma — помечаем
заказчику явно):

- карточки VALUES — без белой заливки, тени и скруглений: номер, заголовок, текст
  прямо на оливковом фоне, разделённые волосяной линией;
- строки FAQ — без серых плашек, только линии-разделители (так и было до 2026-08-20,
  плашки добавляли ради соответствия макету);
- фото-панели ABOUT / FOUNDERS / COLLAB ниже, чем в v8, — оливковые полосы перестают
  быть «на весь экран».

**Футер** масштабируется вместе со страницей (он тоже часть «прохода по странице»).
**Шапка — нет:** она общая с страницами туров и по `design-system.md` намеренно
выведена из закона масштабирования.

## 5. Порядок работ

1. Секция «Облегчённые версии» в `app/globals.css` — переменные + правила по блокам.
2. `components/versions/page-scale.tsx` — установка `data-ona-scale` (клиентский
   компонент + inline-скрипт против мигания).
3. `components/versions/home-light.tsx` — одна обёртка над тем же составом секций,
   что и `HomeV6`, с пропом `scale`. Копирования секций нет.
4. `lib/versions.ts` — три записи (`v7`, `v8`, `v9`, статус `ready`);
   `components/versions/registry.tsx` — три строки.
5. Замер: высота страницы и кегли на 1920 / 1440 / 1280 / 1024 / 390.
   Проверка закона масштабирования (`кегль_W / кегль_1920 × 1920 / W = 100%`),
   проверка, что число строк у контрольных элементов не выросло.
6. Скриншоты каждого блока в трёх вариантах — заказчику для сравнения.
7. Обновить `docs/VERSIONS.md` (таблица версий) и `CLAUDE.md` (ссылка на этот файл).

## 6. Риски

- **Разбивка строк.** Уменьшение кегля без уменьшения ширины колонки меняет число
  строк. Лечится масштабированием `max-width` — см. §3, проверяется замером в п. 5.
- **Мелкий текст на узких экранах.** Пол читаемости обязателен, иначе на 1024
  подписи уйдут под 10 px.
- **`min-height` перестаёт быть ведущим.** Это и есть цель, но у ABOUT / FOUNDERS /
  COLLAB высоту фото-панели задаёт именно строка — надо проверить, что фото не
  вырождается в узкую полосу.
- **Карусели Embla** считают геометрию в JS. Меняем только кегль/отступы, ширины
  слайдов не трогаем, но прогнать отзывы и туры глазами обязательно.
- Заказчик может выбрать «между» вариантами («как v8, но заголовки как v7») —
  архитектура на переменных это позволяет: правится три числа, а не вёрстка.
