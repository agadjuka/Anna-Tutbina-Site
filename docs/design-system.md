# Дизайн-система

Tailwind CSS v4 без `tailwind.config`: вся тема объявлена блоком `@theme` в
[`app/globals.css`](../app/globals.css). Исходные требования заказчика — [brand-guidelines.md](brand-guidelines.md).

## Шрифты

| Переменная | Шрифт | Где применяется |
|---|---|---|
| `--font-heading` | Cormorant Regular | Все `h1`–`h6` (задано глобально в `globals.css`) |
| `--font-body` | Kinetika | `body`, основной текст, `<strong>` |
| `--font-logo` | La Luxes | Логотип «ONÁ» в шапке и футере |
| `--font-logo-subtitle` | MADE TheArtist Script | Подпись «woman space & travel» |

Утилиты: `.font-heading`, `.font-sans`, `.font-logo`, `.font-logo-subtitle`.

### Как менять шрифт

1. Положить файл (`.ttf/.otf/.woff/.woff2`) в `public/fonts/headings|body|logo/`.
2. `npm run update-fonts` — перегенерирует `lib/fonts.ts`.
3. Проверить результат в `lib/fonts.ts` и на странице.

Правила генератора (`scripts/update-fonts.ts`), о них легко споткнуться:

- в `headings/` приоритет у файла со словом *cormorant* в имени, иначе берётся первый попавшийся;
- в `logo/` файл со словом *script* или *theartist* уходит в `--font-logo-subtitle`, остальные — в `--font-logo`;
- начертание определяется по имени файла (`regular` → 400, `bold` → 700 и т. д.);
- **`lib/fonts.ts` править руками бессмысленно** — `prebuild` перезапишет файл при каждой сборке.

## Типографика

- Заголовки автоматически получают `font-heading` + `text-primary` из базового слоя.
- `SectionHeading` — фирменный заголовок секции: горизонтальные линии по бокам, uppercase,
  увеличенный трекинг. Это стандарт для всех секций, не собирайте свой.
- `Heading` (`as="h1..h4"`) — крупный заголовок страницы.
- `Paragraph` — основной абзац, `text-base md:text-xl`.
- `PortableTextContent` — рендер контента из Sanity; следит, чтобы `<strong>` оставался
  шрифтом body и не «прыгал» в размере.
- На мобильных для заголовков включены `word-break: break-word` и `overflow-wrap: anywhere`.

## Утилиты в globals.css

`.shadow-card`, `.shadow-card-hover`, `.shadow-card-elevated` — фирменные тени на базе `primary`.
`.text-gradient`, `.text-gradient-accent`, `.gradient-overlay`, `.decorative-bg` — градиенты.
`.asymmetric-clip`, `.rotate-3d` — декоративные формы. `.scrollbar-hide`, `.truncate-long`,
`.text-balance`, `.text-justify-smooth` — вспомогательные.

## Раскладка и скролл

- `Container` (`max-w-screen-xl`, `px-4 md:px-8`) — единственная обёртка ширины, свою не заводить.
- Контентные блоки внутри контейнера часто ограничены `max-w-4xl` и центрированы.
- Брейкпоинты — стандартные Tailwind, основной переключатель мобильный/десктоп — `md` (768px).
- `Header` пишет свою фактическую высоту в `--header-height`; правило `[id] { scroll-margin-top }`
  использует её, чтобы якорные переходы не заезжали под шапку. Значения по умолчанию заданы
  и в CSS (`64/72/86px` по брейкпоинтам, совпадают с классами шапки) — до гидратации переменная
  обязана существовать, на неё опирается подтяжка полноэкранного HERO. Если меняете шапку —
  не сломайте `ResizeObserver` в `header.tsx` и держите CSS-значения в синхроне с её высотой.
- Глобально `overflow-x: clip` на `html/body/main` — горизонтального скролла быть не должно.

  ⚠️ **Именно `clip`, а не `hidden` — не «оптимизация», а обязательное условие.** При
  `overflow-x: hidden` спека требует посчитать `overflow-y` равным `auto`, и `<body>` с `<main>`
  становятся собственными скролл-контейнерами. Последствия, которые из-за этого уже ловили:
  полноэкранный HERO (подтянут вверх отрицательным `margin-top`) обрезался ровно на высоту
  шапки, оставляя светлую полосу; вложенные скролл-контейнеры «сцепляли» прокрутку и на
  телефоне это ощущалось как залипание; `position: sticky` у шапки считался относительно
  `body`, а не окна. `clip` режет только по горизонтали и скролл-контейнер не создаёт.

### Шапка поверх полноэкранного HERO

Прячется/показывается **через CSS, а не через React-состояние**: `globals.css` ловит страницу
селектором `body:has([data-hero-fullscreen="…"])` и скрывает `[data-site-header][data-shown="false"]`.
JS в `header.tsx` отвечает только за факт прокрутки — ставит `data-shown`.

Так сделано потому, что состояние «на этой странице полноэкранный HERO» на первом кадре React
ещё не знает: шапка успевала отрисоваться видимой и уезжала уже после гидратации — мигание
плюс полоса сверху. CSS знает это до всякой гидратации.

Атрибут `data-hero-fullscreen` ставит сам HERO: `"all"` (v4/v5/v6 — полный экран везде),
`"mobile"` (v3 — только `<lg`), отсутствует у v1/v2. На страницах без него селектор не совпадает
и шапка ведёт себя обычным образом — это важно, иначе на страницах туров сверху висела бы пустота.

## Мотивы интерфейса

- Скругления: `rounded-2xl` у карточек и фото, `rounded-full` у кнопок и иконок.
- Все интерактивные элементы имеют `focus-visible:ring-2 ring-primary` — при добавлении новых
  кнопок фокус-состояние обязательно.
- Переходы 200–500 мс; в базовом слое всем элементам назначен `transition-colors duration-200`.
- Контакты (Telegram, WhatsApp, телефон) появляются в трёх местах: `footer`,
  `floating-contacts`, `want-to-join-button`. **Значения больше не захардкожены** —
  приходят из Sanity (`siteSettingsQuery`, поле `primaryContacts`), заказчик правит сам.

## Закон масштабирования (главная)

> **⚠️ На ГЛАВНОЙ странице с 2026-08-25 действует не этот закон, а более строгий —
> «закон одного множителя»:** каждый размер = `calc(<число при 1280> * var(--ona-u))`,
> `--ona-u = min(100vw / 1280, 1.5px)`. Формулы вида `min(X/1920*100vw, Xpx)` и
> `clamp(12px, …)` на главной больше не применяются: у каждой из них своя скорость
> изменения, и из-за этого переносы строк «съезжали» при смене ширины окна. Ниже —
> исходный закон, он по-прежнему действует на страницах туров и `/custom-tour`.
> Разбор — [`redesign/lightweight-scale-plan.md`](redesign/lightweight-scale-plan.md).


Введён 2026-08-21 после того, как заказчик сформулировал принцип: **на 1920 всё
как в макете, при сужении окна страница ужимается целиком** — ничего не съезжает
и не переносится сверх того, что есть в шаблоне.

### Правило

Любое значение `lg`-ветки — кегль, отступ, зазор, размер элемента — пишется как

```
min(X/1920*100vw, Xpx)
```

где `X` — величина из макета Figma при ширине 1920. Для текста, который иначе
опустился бы ниже читаемого, добавляется пол:

```
clamp(12px, X/1920*100vw, Xpx)
```

Проверка формулы: подставьте 1920 — должно получиться ровно `X`.
Например 17px → `min(0.885vw, 17px)`, 26px → `min(1.35vw, 26px)`.

### Чего делать НЕЛЬЗЯ

**Фиксированный `lg:text-[17px]` или `lg:px-[26px]`.** На 1920 совпадёт с макетом,
а на ноутбуке контейнер сузится, текст останется прежним и полезет в две строки.
Именно так ломались карточки туров (при 1920 карточка 336px, при 1024 — 179px,
а текст оба раза 17/35/20px).

**Пол `clamp` выше, чем нужно.** До правки у всех девяти H2 главной стоял пол
40px при формуле `3vw`: на 1280 формула хочет 38.4px, а пол не пускал — заголовок
оставался крупным при сузившемся контейнере. Это и давало «всё какое-то большое».
Пол существует ради читаемости, а не ради размера: он должен быть **ниже**
макетного значения, иначе элемент станет КРУПНЕЕ макета на узких экранах.

### Исключения (осознанные, не забывать при правках)

| Где | Что | Почему |
|---|---|---|
| Шапка сайта | не масштабируется | общая для всех страниц, в «съезжаниях» главной не участвует |
| Футер | полы 9–11px вместо 12px | подписи и в макете набраны 11px; пол 12px сделал бы их крупнее макета |
| Теги COLLAB | пол снят совсем, `min(0.78vw, 15px)` | требование «в одну строку» плюс граница по краю заголовка несовместимы с полом 12px |
| Страница тура | свой закон | в Figma не рисовалась, эталона 1920 нет; ширина блоков — `lib/tour-layout.ts` |

### Как проверять

Скриптом на нескольких ширинах сразу: для каждого контрольного элемента
`кегль_на_W / кегль_на_1920 × 1920 / W` должно давать 100% (либо элемент стоит
на полу). Плюс число строк у каждого элемента должно совпадать с 1920 — если
где-то строк больше, значит что-то не ужалось вместе с контейнером.
