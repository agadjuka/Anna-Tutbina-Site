## Как поддерживать документацию

Документы описывают **намерение и связи**, которые не видны из кода. Не дублируйте сюда то,
что и так читается в файлах (списки пропсов, тела функций) — такое устаревает первым.

Обновлять обязательно, если изменили:

- схему Sanity или GROQ-запрос → `content-model.md`;
- список роутов, стратегию рендеринга, middleware → `architecture.md`;
- палитру, шрифты, глобальные стили → `design-system.md`;
- команды, переменные окружения, процесс деплоя → `development.md` и `../README.md`;
- что-то из списка техдолга (починили или добавили) → `known-issues.md`.
