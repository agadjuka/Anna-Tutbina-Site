## ✅ Исправлено в ходе аудита

### 1. Синтаксическая ошибка ломала Sanity Studio — `sanity/schemas/tour.ts:310`

В описание поля `hideFromSite` попали три случайных символа:

```ts
description:
изь        'Если включено: тур не в списке...',
```

Это невалидный JS: схема не парсилась, Studio не собиралась. Попало в репозиторий с коммитом
`1c43825 «Деплой»` и с тех пор лежало незамеченным, потому что `sanity/` исключён из
`tsconfig.json` фронтенда и его никто не проверял. Мусор убран.

### 2. `npm run lint` был непригоден

ESLint обходил `sanity/dist/**` — минифицированную сборку Studio — и выдавал **3389** проблем,
среди которых терялись 58 реальных. В `eslint.config.mjs` добавлены игноры
`sanity/dist/**` и `sanity/node_modules/**`. Стало 58 ошибок и 15 предупреждений по своему коду.

### 3. `.vscode/settings.json` — невалидный JSON

Файл начинался сразу с ключа, без внешних фигурных скобок: VS Code настройки игнорировал.
Скобки добавлены.

### 4. Не было шаблона переменных окружения

Добавлен `.env.example`. Раньше единственным описанием env был README.

### 5. `sanity/tsconfig.json` без `moduleResolution` — типы схем не проверялись вообще

При `"module": "ESNext"` резолвер откатывается в `classic`, и TypeScript не находил ни одного
модуля: `TS2792` на каждом импорте (`Cannot find module 'sanity'`). Зависимости Studio при этом
установлены — дело было только в конфиге. Из-за этого шума любые настоящие ошибки в схемах были
невидимы, именно так и прожил год баг №1.

Добавлено `"moduleResolution": "bundler"`. Теперь `npx tsc --noEmit -p sanity/tsconfig.json`
проходит чисто — прогонять после любой правки в `sanity/`.

### 6. `reviewItem`: опция `rows` стояла не там и не работала

`sanity/schemas/reviewItem.ts` — поле «Текст отзыва» объявляло `options: { rows: 6 }`, но у типа
`text` в Sanity `rows` — свойство верхнего уровня, а не опция. Studio молча игнорировала настройку,
поле отзыва рендерилось в стандартную высоту. Найдено сразу после №5 — это первая ошибка, которую
поймала заработавшая проверка типов. `rows` поднят на верхний уровень.

### 7. Бриф по фирменному стилю лежал в корне

Файл `правки` без расширения перенесён в [`brand-guidelines.md`](brand-guidelines.md)
(через `git mv`, история сохранена), текст брифа оставлен как есть.

### 8. README устарел

Было заявлено «Next.js 16.0.1» при фактических 16.0.10; не описаны `update-fonts`, `prebuild`,
`reinstall`; ссылки на Studio и Vercel — плейсхолдеры «ссылка после деплоя»; нет ни слова
о действующих ограничениях доступа. Переписан. **Ссылки на задеплоенную Studio и на проект
Vercel всё ещё нужно проставить руками** — у агента этих URL нет.

## 🔴 Высокий приоритет

### 8.5. `/tours/kas` отдаёт 404 — а это точка входа для всего сайта

Обнаружено 13 августа 2026 при проверке прода после деплоя. `/tours/kas` и
`/tours/bali-padelsurfcamp` отвечают **404**, остальные четыре тура из `allowedPaths` — 200.

Почему это критично: `/tours/kas` — `defaultRedirect` в `middleware.ts`, то есть **любой
посетитель, зашедший на домен без конкретного адреса, попадает именно туда**. Сейчас он
попадает на 404.

Код не менялся — похоже на состояние контента: тур снят с публикации в Sanity либо помечен
`hideFromSite` (флаг выключает тур и по прямой ссылке, см. [architecture.md](architecture.md)).

**Что делать:** проверить статус этих двух туров в Studio. На будущее — редирект по умолчанию
не должен указывать на документ, который редактор может незаметно скрыть: либо выбирать первый
доступный тур из `allowedPaths` динамически, либо отдавать осмысленную страницу-заглушку.

### 9. 47 `any` вокруг данных Sanity

`any` во всех местах, где приходит контент: `image: any`, `bio: any`, `introText: any`,
`dayImage?: any[]`, `mainImage: any` и т. д. Больше всего — `app/tours/[slug]/page.tsx` (15).
Из-за этого опечатка в имени поля GROQ не ловится ни компилятором, ни линтером и проявляется
пустым блоком на проде.

**Что делать:** завести `lib/types/sanity.ts` с общими типами (`SanityImageRef`, `PortableTextValue`,
`Tour`, `TourReview`, `PricingDetails`, `FaqItem`) и заменить `any` на них. Начать с
`app/tours/[slug]/page.tsx` и `lib/utils/reviews.ts`.

### 10. `sitemap.xml` и canonical рекламируют страницы, закрытые middleware

`sitemap.ts` отдаёт `/` и `/custom-tour`, `layout.tsx` объявляет canonical `/`, а middleware
редиректит и то, и другое на `/tours/kas`. Поисковик получает противоречивые сигналы:
canonical ведёт на URL, который отвечает редиректом.

**Что делать (пока ограничения включены):** формировать sitemap из того же списка `allowedPaths`
и вынести этот список в общий модуль (например, `lib/site-access.ts`), чтобы middleware и sitemap
не расходились. Либо честно закрыть индексацию до снятия ограничений.

### 11. `/admin` — обход без какой-либо защиты

Префикс `/admin` открывает весь сайт целиком, `robots.txt` разрешает индексацию всего, у страниц
под `/admin` нет `noindex`. Достаточно одной внешней ссылки — и в индекс попадёт дубль всего сайта.
Это не «дыра в безопасности» (секретных данных за префиксом нет), но SEO-риск реальный.

**Что делать:** в middleware для ветки `/admin` добавлять заголовок `X-Robots-Tag: noindex, nofollow`
и запретить `/admin` в `robots.ts`.

### 12. `middleware` депрекирован в Next 16

Сборка предупреждает: конвенция `middleware` заменена на `proxy`. Сейчас работает, но исчезнет
в будущей мажорной версии.

**Что делать:** переименовать `middleware.ts` → `proxy.ts` по официальному гайду,
проверив, что `/admin`-rewrite и редиректы не изменили поведение.

## 🟡 Средний приоритет

### 13. `react-hooks/set-state-in-effect` — 9 ошибок

`accommodation-carousel.tsx:94,105`, `program-days-carousel.tsx:96,107`,
`expandable-review-text.tsx:65,84`, `reviews-embla.tsx:123`, `tours-embla.tsx:84`,
`tour-gallery.tsx:40`.

Синхронный `setState` в теле эффекта даёт каскадные рендеры. На каруселях с
`ResizeObserver`/Embla это заметно на слабых мобильных: лишний проход layout на каждой инициализации.

**Что делать:** разбирать по одному, приоритет — карусели туров и отзывов (видны на главной).
Часть случаев снимается вычислением значения во время рендера или переходом на
`useSyncExternalStore`.

### 14. `program-days-carousel` и `accommodation-carousel` — дубликаты на ~85 %

401 и 432 строки, различия — только имена полей (`dayTitle`/`locationName`,
`dayImage`/`locationImages`), подписи и `containScroll: "trimSnaps"` против `"keepSnaps"`.
Любая правка карусели сейчас требует двух одинаковых правок, и они уже начали расходиться.

**Что делать:** вынести общий `MediaCarousel` (слайды + лайтбокс + стрелки + точки), а два
существующих компонента оставить тонкими адаптерами, приводящими данные к общей форме.

В коде значений больше нет.

### 16. `SanityImage` строит JSX внутри `try/catch`

`components/ui/sanity-image.tsx:47,58` — 2 ошибки `react-hooks/error-boundaries`. React не рендерит
JSX в момент создания, поэтому `catch` не поймает ошибку рендера: фолбэк «Ошибка загрузки»
не сработает никогда, а переменная `error` не используется.

**Что делать:** оставить в `try` только построение URL через `urlFor()` (единственное, что
реально бросает), JSX вынести наружу. Заодно удалить неиспользуемый импорт `cn` (строка 3).

### 17. Три сырых `<img>` вместо `next/image`

`recommended-flights-section.tsx:37`, `tour-gallery.tsx:111,179` — картинки с `cdn.sanity.io`
идут мимо оптимизации Next: без WebP/AVIF, без правильных размеров. В галерее это тяжелейшие
изображения на сайте.

**Что делать:** перевести на `SanityImage`/`next/image` там, где не мешает лайтбокс; для лайтбокса
проверить требования `yet-another-react-lightbox` к разметке.

## 🟢 Низкий приоритет / гигиена

### 20. `.env` и `.env.local` дублируют друг друга

Два файла с одинаковым содержимым. Next читает оба (приоритет у `.env.local`), так что
расхождение между ними однажды приведёт к «у меня работает». Стоит оставить только `.env.local`.

### 21. Нет тестов и CI

Ни одного теста, нет GitHub Actions. Любая регрессия ловится только руками.

**Что делать (минимум):** workflow на пуш/PR с `npx tsc --noEmit`,
`npx tsc --noEmit -p sanity/tsconfig.json`, `npm run lint`, `npm run build`.
Этого достаточно, чтобы ошибка уровня №1 не дожила до прода. Юнит-тесты имеют смысл прежде всего
для `lib/utils/*` — там чистые функции.

### 22. История коммитов

Сообщения вида «Итог», «1», «Появилось», «правки»; всё пишется прямо в `master`, веток нет.
Разобраться, когда и зачем что-то менялось, невозможно — баг №1 год пролежал в коммите «Деплой».

**Что делать:** договориться о минимальном формате («что изменилось + зачем») и делать заметные
